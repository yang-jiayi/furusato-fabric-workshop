## Executed relationship evidence (highest priority)
This source executes two kinds of instance queries in addition to declaration lookups.
Name matching: PrefectureName holds the Japanese name with its suffix (都/道/府/県), and MunicipalityName holds the Japanese municipality name. Match a user's prefecture as the Japanese suffixed name (add 都/道/府/県 when omitted) or by PrefectureId; never translate a Japanese name to English for PrefectureName. If a name lookup returns no rows, retry once with the suffix-normalized Japanese name, PrefectureNameEn or a prefix match before reporting that it does not exist.
Membership COUNT: for the number of municipalities in a prefecture, aggregate over the declared edge and return PrefectureId, PrefectureName and MunicipalityCount, for example:
MATCH (m:Municipality)-[:MunicipalityInPrefecture]->(p:Prefecture) WHERE p.PrefectureId = <id> RETURN p.PrefectureId AS PrefectureId, p.PrefectureName AS PrefectureName, count(m) AS MunicipalityCount GROUP BY PrefectureId, PrefectureName
The declared edge is Municipality -MunicipalityInPrefecture-> Prefecture; counting members from the prefecture is the reverse traversal Prefecture <-MunicipalityInPrefecture- Municipality. Do not list every member unless asked.
Forward prefecture lookup: for given MunicipalityId values (STRING with leading zeros; never compare with a number) return the prefecture through the forward traversal Municipality -MunicipalityInPrefecture-> Prefecture, for example:
MATCH (m:Municipality)-[:MunicipalityInPrefecture]->(p:Prefecture) WHERE m.MunicipalityId = '<MunicipalityId>' RETURN m.MunicipalityId AS MunicipalityId, p.PrefectureId AS PrefectureId, p.PrefectureName AS PrefectureName
Exact donation instance path: for one DonationId return DonorId, DonationId, MunicipalityId, recipient PrefectureId, GiftId, CategoryId and every SupplierId through Donor -DonorMadeDonation-> Donation -DonationToMunicipality-> Municipality -MunicipalityInPrefecture-> Prefecture, Donation -DonationSelectedGift-> Gift -GiftInCategory-> GiftCategory and Gift <-SupplierProvidesGift- Supplier. Attribute values and names still come from Lakehouse SQL.
