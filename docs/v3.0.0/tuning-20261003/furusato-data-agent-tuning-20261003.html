実装した改善 / Implemented changes

全体指示と4ソースの指示を整理し、静的seed・原始観測・Goldを分離しました。質問の意味、必須のID/名前/県情報、全件一覧、UTC/JST、BLANK、宣言向きと探索向きを明示しています。数値の正しさだけでなく、必須項目と説明の正しさも判定しています。

既存4ビューに加え、実Ontology定義の15関係を照合したagent_relationship_dictionaryと、格納キー・両側のID/名前・指標・宣言方向を揃えたagent_prefecture_category_metricを追加しました。662指標行、80,000寄附、1,344,099,000円を維持し、全キー/値の一致とSQL定義のreadbackを確認しました。これはスキーマ情報のSQLビュー化であり、元データやOntology定義の変更ではありません。

比較用Agentだけで2ビューを選択し、重複する元の県別カテゴリ指標テーブルを選択解除しました。サービスが検出したview型・ID・列型を使用し、架空のtableノードを作っていません。主Agent、元の比較候補、主Ontology、モデルメジャー、Notebook01/05の実行回数は保持しています。

後続の質問で空結果の誤判定、本人情報の欠落、高額フラグの比較記号の誤説明が見つかったため、実データの値ドメイン、短い一覧でも必要な本人情報、Notebook05由来の厳密な57,000円超・同額除外を明示しました。最終例はSQL15件・KQL5件です。特定質問の正答件数や合計金額は埋め込まず、57,000円は元Notebookの既存ビジネスルールとして扱っています。

The native candidate separates static seed, raw observations and source-owned Gold measures, retains required business identities, and distinguishes declared relationship direction from traversal direction.

Two additive SQL views expose verified Ontology declarations and existing metric keys without changing base data, original views, the main Agent, the Ontology or model measures. Direct queries and native example admission are separate from answer-quality judgments.

Every configuration and first-pass failure is retained. The expanded run reuses complete question/oracle/criterion objects on one new configuration; formerly unused questions used for correction are now development cases, not independent validation.

適用と確認 / Apply and verify

比較用Agentを使い、既存の主Agentと履歴を保持します。データ取得先・関係スキーマ・最終回答列を分けて設定します。

SQL/KQL例は実ソースで確認した後、Setup > 各データソース > Example queries でエラーと検証待ちがないことを確認します。直接SQLが成功しただけではAgent内の例の参照を証明しません。

設定の前後と公開後に定義を読み戻します。質問・期待値・必須条件を固定し、構成ごとに各問1回だけ送信します。通信エラー、不明、未送信を分母から除外しません。

一覧はソース側の全件数と表示ID集合を照合し、ランキングは安定IDで順序を確定します。暦年とsnapshot名、観測時刻と合成配信メタデータ、BLANKと0を区別します。

残る事項 / Remaining findings

拡大32枠の最終結果は29 PASS /2 FAIL /1 UNKNOWNです。UTCと明示された時間集計をJST日に読み替える問題、GoldメジャーのStaticSeed条件を静的SQLのStaticSyntheticSnapshotと取り違えて説明する問題が残りました。0 FAIL・全問合格としては扱いません。追加試験で発見した電子決済の空結果、本人情報の省略、高額フラグの同額包含の3問題は、この構成では改善を確認しましたが、別の退行を隠していません。

拡大32枠の初回実行は11業務回答の後、1問のHTTP500（native内部エラー）と、次の問の送信前定義取得タイムアウトで停止しました。送信結果不明の1問は再送せず保持しています。定義の読み取りが再び成功し同一構成を確認できた後、元の未送信20枠だけを各1回処理する、事後の明示的な手順変更を行い、20業務回答を取得しました。これは事前登録済みの再開機能ではなく、元の停止記録・不明送信・全32枠を保存した追加続行です。取得済み31回答を審査し、不明1枠をUNKNOWNのまま残しています。

任意の将来質問に対する無誤答や、100問全体の品質合格を保証する結果ではありません。追加の質問を改善に用いた後は、その質問を独立した未使用検証として扱いません。主Agentへは昇格していません。
