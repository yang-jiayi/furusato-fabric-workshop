# Explicit evidence-first candidate

This is an opt-in authoring profile, not a promoted baseline or an accepted
accuracy result. The local compiler preserves all four source identities,
selected elements, runtime and Code Interpreter settings. It changes generic
guidance and reusable query examples only; it does not modify source records,
model measures or Ontology generation.

For donation traces, the complete SQL attribute ledger includes every catalog
supplier ID/name and explicit source, snapshot and grain columns. A separate
native GQL query establishes modeled connectivity. Graph-returned properties
do not replace missing SQL attributes, and catalog registration does not prove
manufacture, shipment or fulfillment. Supplier-prefecture fields belong in the
SQL projection if displayed. Attribute every extra field to its actual returned
engine; a blanket claim that all attributes came from SQL is invalid when an
answer adds even one GQL-only property. Keep a source-role ledger in the final
answer and never sum a donation amount repeated across supplier rows.

The SQL example uses a non-benchmark identifier; operational examples resolve
available years instead of inheriting the static snapshot year. No example
contains expected answers. Validate query shape and native answers separately,
preserve failed campaigns, and do not bypass a native content block or invent
queries for a responsible refusal.
