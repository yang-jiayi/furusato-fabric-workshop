# 24.2 操作手順

[Lab 目次](../README.md) · [この章の目次](README.md)

1. 初回は24.4で本人認証とフォルダー対応を確認し、24.5で配置計画を読み、自分の許可された範囲だけを書き込み承認します。
2. 24.6でソース、Notebook、Pipeline、Activator、主Ontologyを配置します。deploy-realtime は初回取り込みと Activator 用ファイルのアップロードより前に、DonationEvents だけの parquet mirroring（IsEnabled=true、TargetLatencyInMinutes=5）を有効にする前提です。8章で所有範囲・フォルダー・schema・RLS・既存 policy と安全な読み取り結果を確認し、未確認または互換でない場合は停止します。5〜8章は作成済みの内容を確認するために使い、同じものを追加しません。
3. 24.7と9〜10章で増分3ファイルを各1回取り込み、11章でNotebook05のプレビューと適用を実施します。24.8でモデルとAgentを作り、17章で調整済み構成、19章で回答を評価します。
4. 運用時は、データ更新、Graph更新、Metrics更新、Version history、回答再評価を別の作業として記録します。設定変更時は公開版を保存し、何を変えたかを記録します。
5. ワークショップ終了後のクリーンアップは、所有者または講師の明示的な事前承認を得てから行います。Activatorを停止し、Pipeline・Notebookの実行中ジョブがないことを確認して、評価記録を保存します。承認された自分の参加者IDの項目だけを、Data Agent→Power BIレポート（作成した場合）→Semantic model→主Ontologyと管理されたGraph→Activator→Pipeline→Eventhouse→Notebook→Lakehouseの依存順で削除します。別のフォルダーや他の人の項目、作業フォルダー、ワークスペース、容量、ロール、テナント設定は削除しません。削除済みアイテムの完全消去には別途所有者承認が必要です。削除が失敗したら繰り返さず、残る参照を確認します。

> 所有者または講師の明示的な事前承認がない限り、クリーンアップを行いません。別のフォルダーや他の人の項目、作業フォルダー、ワークスペース、容量、ロール、テナント設定は削除対象外です。削除済みアイテムの完全消去には別途所有者承認が必要です。

## 24.2 Steps

1. On the first run, authenticate and verify folder mapping in 24.4, then review the concrete plan and authorize writes only in your permitted scope in 24.5.
2. Deploy sources, Notebooks, Pipeline, Activator and the main ontology in 24.6. Use Chapters 5–8 to inspect the created resources without adding duplicates. deploy-realtime must enable DonationEvents-only parquet mirroring (IsEnabled=true, TargetLatencyInMinutes=5) before first ingestion and before uploading any Activator input. In Chapter 8 verify ownership scope, folder, schema, RLS, the existing policy and safe readback; stop if unverified or incompatible.
3. Ingest each of the three increments once through 24.7 and Chapters 9–10, then preview and apply Notebook05 in Chapter 11. Create the model and Agent in 24.8, configure the adopted tuning in Chapter 17 and evaluate answers in Chapter 19.
4. In operation, record data updates, Graph refresh, Metrics refresh, Version history and answer reevaluation as separate activities. Save the current publication before changing settings and record each change.
5. Clean up after the workshop only with explicit prior approval from the owner or instructor. Stop the Activator, confirm no Pipeline or Notebook jobs are running, and save evaluation records. Delete only approved resources bearing your participant ID, in dependency order: Data Agent → Power BI report if created → semantic model → main ontology and managed Graph → Activator → Pipeline → Eventhouse → Notebooks → Lakehouse. Do not delete other folders or anyone else’s items, the work folder, workspace, capacity, roles or tenant settings. Permanent purging of deleted items requires separate owner approval. If deletion fails, inspect remaining references instead of retrying repeatedly.

> Do not clean up without explicit prior approval from the owner or instructor. Other folders and anyone else’s items, the work folder, workspace, capacity, roles and tenant settings are out of scope for deletion. Permanent purging of deleted items requires separate owner approval.
