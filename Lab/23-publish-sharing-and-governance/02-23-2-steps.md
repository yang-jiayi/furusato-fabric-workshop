# 23.2 操作手順

[Lab 目次](../README.md) · [この章の目次](README.md)

1. 公開する Ontology の定義と、Data Agent の指示・ソースを、19章の評価の記録（ブロックや失敗を含む）と一緒に見直します。評価していない構成について、成功率を示しません。
2. 講師が指定した Data Agent だけを Publish します。公開後、公開版のソースと指示が意図どおりであることを確認します。
3. Share で共有するときは、必要な人に、必要な最小の権限だけを付けます。Ontology や Data Agent の Read 権限があっても、元の Lakehouse・Eventhouse・Semantic model を読めるとは限りません。
4. 行・列・オブジェクト単位のセキュリティ（RLS・CLS・OLS）や OneLake の権限は、元データの側で設定・確認します。Rules、Namespace、指示（プロンプト）はアクセス制御ではありません。
5. 講師がテスト用のアカウントを用意している場合は、そのアカウントで、静的データ・8月の観測データ・登録の経路について1問ずつ試します。用意されていない場合は、この確認を省略したことを記録します。権限を自分で追加しません。
6. 画面を共有したり、資料に画面の画像を貼ったりするときは、アカウント名、URL、ワークスペースやアイテムの ID、パスが写らないようにします。

> 説明用の Metadata や Rules は、セキュリティの設定を上書きしません。

## 23.2 Steps

1. Review the ontology definition and the Data Agent's instructions and sources together with your Chapter 19 evaluation records (including blocked and failed items). Do not report success rates for configurations you have not evaluated.
2. Publish only the Data Agent that the instructor specifies. After publishing, confirm that the published version's sources and instructions are as intended.
3. When you share with Share, give only the minimum permissions to the people who need them. Read permission on the ontology or the Data Agent does not guarantee that the user can read the source Lakehouse, Eventhouse or semantic model.
4. Set and check row-, column- and object-level security (RLS, CLS and OLS) and OneLake permissions on the source data side. Rules, namespaces and instructions (prompts) are not access control.
5. If the instructor provides a test account, use it to try one question each about static data, August observation data and the registration path. If none is provided, record that you skipped this check. Do not add permissions yourself.
6. When you share your screen or paste screenshots into documents, make sure that account names, URLs, workspace and item IDs and paths are not visible.

> Descriptive metadata and Rules do not override security settings.
