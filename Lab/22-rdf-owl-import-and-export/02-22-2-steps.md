# 22.2 操作手順

[Lab 目次](../README.md) · [この章の目次](README.md)

1. 主 Ontology の Home の Export が表示される場合は、TTL または RDF をダウンロードします。OWL のエクスポートとして拡張子だけを書き換えません。
2. 配布の TTL とエクスポートしたファイルを、テキストで比較します。Entity、Property、Relationship、label、comment、型、関係の向きを確認します。実際に異なる項目を記録し、件数だけで同じモデルと判断しません。サービスが補った外部キー、long から integer への型の拡張、時系列 Property の range 欠落も比較対象です。
3. 配布のファイルはバインド、キー、同義語、native 時系列の動作や Metrics の実行を再現するものではありません。RDF の構造の一致と、Fabric の実データ照会・機能の完了を区別します。
4. 既存の内容に RDF をマージする import はできません。この標準手順では、空の別 Ontology を作る import や再 import は行いません。主 Ontology の内容も消しません。

> Export が使えない場合は、理由を記録し、配布の TTL の構造の読み取りだけを行います。

## 22.2 Steps

1. If Export appears on the main ontology Home, download TTL or RDF. Do not merely rename a file extension and call it an OWL export.
2. Compare the distributed TTL and the export as text. Check entities, properties, relationships, labels, comments, types and relationship direction. Record actual differences; matching counts alone do not establish the same model. Include service-generated foreign keys, widening from long to integer, and missing ranges on time-series properties.
3. The distributed file does not reproduce bindings, keys, synonyms, native time-series behavior or Metrics execution. Distinguish matching RDF structure from live Fabric queries and feature completion.
4. RDF import cannot merge into existing content. This standard procedure does not create another empty ontology for import or reimport, and does not clear the main ontology.

> If Export is unavailable, record the reason and inspect only the distributed TTL structure.
