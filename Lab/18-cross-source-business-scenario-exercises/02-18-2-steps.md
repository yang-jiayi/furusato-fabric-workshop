3. シナリオC（登録と発送）：16章で使った GiftId を1つ選び、GQL と SQL で登録されている Supplier を確認します。次に Data Agent に同じ GiftId で質問し、回答が「登録」と「発送」を区別しているかを確認します。

4. シナリオD（DAX）：Semantic model を直接ソースにした Data Agent に次の質問をします。直接実行した DAX と、Agent の実際の DAX・結果で、同じ条件（StaticSeed）が使われているかを確認します。主 Ontology の Metrics は設定済みで利用可能な場合だけ別に比較します。

5. シナリオE（グラフ）：Code Interpreter には確認済みの集計だけを渡してグラフにし、タイトルに期間・単位・対象（分母）を入れます。保存済みの順位（MunicipalityAmountRank など）と、今回の条件で計算した順位を区別します。
6. シナリオごとに、使われたエンジン、粒度、期間、値を表にまとめ、静的データと観測データを足していないか、存在しない経路を作っていないかを確認します。

> シナリオの質問は練習用です。19章の評価に使う10問とは別の質問を使います。

## 18.2 Steps

1. Scenario A (geographic meaning): ask the Data Agent the following. Confirm that (1) donations received, 2,661 / JPY 45,930,000, and (2) donations by residents, 8,784 / JPY 146,543,000, are shown separately with labels.

**Readable prompt — English**

<div>
Using the static data (donations in 2025), show the count and amount for Tokyo separately for (1) donations received by municipalities in Tokyo and (2) donations made by donors who live in Tokyo. Also show the source and conditions you used.
</div>

**Verbatim prompt follows.**

```text
Using the static data (donations in 2025), show the count and amount for Tokyo separately for (1) donations received by municipalities in Tokyo and (2) donations made by donors who live in Tokyo. Also show the source and conditions you used.
```

2. Scenario B (August observations): in the KQL queryset, use the queries from Chapter 10 to confirm 15,000 rows / JPY 253,886,000 including duplicates and 14,900 unique EventIDs. Then ask the Data Agent the following and check that the answer is 452025 with 331 observations / JPY 5,737,000, labeled as including duplicates.

**Readable prompt — English**

<div>
In the August 2026 observation data, show the MunicipalityId of the municipality with the most observations, together with its observation count and observed amount. State whether the values include duplicates.
</div>

**Verbatim prompt follows.**

```text
In the August 2026 observation data, show the MunicipalityId of the municipality with the most observations, together with its observation count and observed amount. State whether the values include duplicates.
```

3. Scenario C (registration versus shipment): pick one GiftId used in Chapter 16 and check the registered suppliers with GQL and SQL. Then ask the Data Agent about the same GiftId and check that the answer distinguishes registration from shipment.

**Readable prompt — English**

<div>
Show all suppliers registered for the gift with GiftId &lt;GiftId&gt;, with SupplierId and name. Also explain what this relationship means and what it does not mean.
</div>

**Verbatim prompt follows.**

```text
Show all suppliers registered for the gift with GiftId <GiftId>, with SupplierId and name. Also explain what this relationship means and what it does not mean.
```

4. Scenario D (DAX): ask the following of the Data Agent with the semantic model as a direct source. Compare direct DAX with the agent's actual DAX and result under the same StaticSeed condition. Compare main-ontology Metrics separately only if configured and available.

**Readable prompt — English**

<div>
Show 寄附総額 where the data source is StaticSeed. Also show the DAX you ran and the name of the measure you used.
</div>

**Verbatim prompt follows.**

```text
Show 寄附総額 where the data source is StaticSeed. Also show the DAX you ran and the name of the measure you used.
```

5. Scenario E (charts): give Code Interpreter only totals you have already checked, and put the period, unit and scope (denominator) in the chart title. Distinguish stored ranks (such as MunicipalityAmountRank) from ranks calculated under the current conditions.
6. For each scenario, put the engine, grain, period and values in a table, and check that static and observation data were not added together and that no non-existent path was invented.

> The scenario questions are for practice. Use questions that differ from the ten evaluation questions in Chapter 19.
