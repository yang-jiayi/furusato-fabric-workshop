5. Table view に切り替え、ID・名前・関係の向きを確認します。Node に表示される数字は順位などの場合があり、業務の ID とは限りません。ID は Table view のプロパティで確認します。
6. GQL を実行できる画面で、次の GQL を実行します。ラベル名は、Components に表示された名前をそのまま使います（Namespace の接頭辞が付いている場合も含めて）。

**GQL**

```gql
MATCH (s:Supplier)-[r:SupplierProvidesGift]->(g:Gift)
RETURN s.SupplierId, g.GiftId
LIMIT 20
```

7. SQL analytics endpoint で次の SQL を実行し、同じ GiftId のキーの組を比べます。GQL の20行は並び順を指定していないため、SQL の20行と同じ組になるとは限りません。同じ GiftId で絞った結果どうし、または件数（SupplierProvidesGift は 14,514）で比べます。

**SQL**

```sql
SELECT TOP (20) SupplierId, GiftId
FROM dbo.ot_supplier_gift
ORDER BY SupplierId, GiftId;
```

8. 元データを更新しても、Graph は自動では更新されません。講師の指示があるときに、現在の projection と source の適格性を先に確認します。時系列の追加で Unsupported や drift が生じた場合は、load 済みの静的モデルと同期候補を区別して記録し、未対応の候補を実体化しません。更新可能な場合だけ … → Schedule → Refresh now を使い、元データの時点を記録して照合し直します。

> 通常の件数や合計は SQL・KQL・DAX で求めます。GQL は、関係の経路が問われるときに使います。

> 多対多の SupplierProvidesGift をたどって寄付金額を集計すると、同じ寄付を重複して数えることがあります。関係の登録と、実際の発送を区別します。

## 16.2 Steps

5. Switch to Table view and check IDs, names and the direction of relationships. Numbers shown on nodes may be ranks or similar values, not business IDs. Check IDs in the properties shown in Table view.
6. On a screen where you can run GQL, run the following GQL. Use the label names exactly as shown in Components (including any namespace prefix).

**GQL**

```gql
MATCH (s:Supplier)-[r:SupplierProvidesGift]->(g:Gift)
RETURN s.SupplierId, g.GiftId
LIMIT 20
```

7. Run the following SQL in the SQL analytics endpoint and compare the key pairs for the same GiftId. The GQL query does not specify an order, so its 20 rows are not necessarily the same pairs as the 20 SQL rows. Compare results filtered by the same GiftId, or compare counts (14,514 for SupplierProvidesGift).

**SQL**

```sql
SELECT TOP (20) SupplierId, GiftId
FROM dbo.ot_supplier_gift
ORDER BY SupplierId, GiftId;
```

8. A graph does not update automatically with its source. When the instructor requests an update, first check the current projection and source eligibility. If time-series changes produce Unsupported sources or drift, record the loaded static model separately from the synchronization candidate and do not materialize an unsupported candidate. Use … → Schedule → Refresh now only when supported, then record the source state and compare again.

> Use SQL, KQL or DAX for ordinary counts and totals. Use GQL when the relationship path is the question.

> Aggregating donation amounts through the many-to-many SupplierProvidesGift can count the same donation more than once. Distinguish registration relationships from actual shipment.
