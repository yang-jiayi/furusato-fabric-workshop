Gift output describes the selected gift only. Never describe it as received, delivered, shipped or fulfilled, including in a heading, bullet or summary. For approved TVFs return SELECT * or alias.* with every native column name and value unchanged. Do not project a subset, rename a field, or add synthetic source/capability columns. Permit SELECT * or alias.* only from the two bounded approved TVFs. Wildcards are forbidden for the view, dbo tables, joins and other functions. Do not add parameters, native return columns or invented types.

BASE TABLES, ROLES AND GRAIN
Use dbo facts/dimensions for overall totals, name resolution, explicitly filtered aggregation and other Core facts. ot_donation is one Donation row per donation. COUNT_BIG(*) is appropriate on unjoined Donation rows; after a zero-preserving dimension join count non-null d.DonationId with COUNT_BIG(d.DonationId), not dimension rows. Never aggregate Donation facts through ot_supplier_gift or another many-side join.
The dimension and pair-metric tables already contain grain-specific pre-aggregates. Do not sum overlapping pre-aggregates at a different grain. Keep requested zero-participation members. Successful valid scalar aggregates returning zero are confirmed zero with scope/units; an unavailable query or a missing entity row is not zero.
Municipality is recipient context. PrefReceived* means received by Municipalities in a Prefecture; PrefResident* means made by its residents. Resolve bare named-Prefecture donation phrases to both role-specific count/amount pairs or clarify the role, never silently choose/add them or infer overlap. ot_pref_donation_flow origin is residence; destination is recipient.
For explicit JST month/day questions use DonationYearMonthJst (yyyy-MM) or DonationDateJst (yyyy-MM-dd). DonatedAtUtc is UTC. Derive filtered ranks in the filtered aggregate using metric descending and stable ID ascending; dbo *AmountRank columns remain amount-only. DonorOverallAmountRank and DonorResidenceAmountRank are nationwide and residence-Prefecture ranks, respectively. A newly computed filtered rank must be labeled as derived and retain its actual filter scope; a recipient-prefecture-only rank is not the nationwide all-donation rank.
Resolve names to all matching IDs before exact filtering; never exact-match a partial/non-unique name. Every named result retains its stable same-row ID. MunicipalityId is text: preserve leading zeros in SQL output, handoffs and exports. Gift category requests retain GiftId/name and CategoryId/CategoryName, keeping catalog, selected/unselected sets and an explicit month separate; unselected does not prove unavailable inventory.
